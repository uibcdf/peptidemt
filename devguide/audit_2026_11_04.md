# Scientific software audit — 2026-11-04

Status: **review recorded; recommendations are not implementation approvals**.
Requested by the investigators on 2026-11-04. This first assessment focused on
modern HydrAMP and its PeptideMT integration. It is not an exhaustive audit of
PeptideMT against its full scientific purpose.

Navigation: [design guide](README.md) · [scientific trajectory](scientific_trajectory.md).
Existing review owners: [HydrAMP #4](https://github.com/uibcdf/hydramp/issues/4)
and [PeptideMT #32](https://github.com/uibcdf/peptidemt/issues/32).

## Scope and method

Read the modern inference, encoder, generation, checkpoint, PCA and descriptor
code, representative mathematical tests, consumer input/result/selection and
execution boundaries, and retained qualification records. Recomputed the seven
dev4 runtime source hashes and retained dev3/dev4 wheel hashes against
[E1's receipt](evidence/hydramp_encoder_E1.json); all matched. Reviewed E2 and
the confidence/H4 receipts without importing scientific frameworks or loading
parameters. No new tests, model evaluations or performance measurements ran.

The reviewed provider is local/uncommitted. Its original Git base is not a
commit of the modern port. Dev3 remains the exact D41 generation resource;
dev4's encoder has separate finite evidence. The
[analogue A1 checkpoint](evidence/hydramp_analogue_A1_pause.json) retains authorized
artificial implementation drafts that are unbuilt and untested. That work stays
paused. No source modification, new scientific acceptance or execution budget
follows from this audit.

## Assessment recorded today

**Verdict:** a well-structured experimental inference core with convincing
finite numerical evidence; incomplete independent product delivery and no
demonstrated biological superiority. PeptideMT has a useful foundation, but
its present assessment data types remain tied to Macrel.

### Correctness and engineering strengths

- Explicit original recurrent equations, including reset-before GRU semantics,
  rather than assuming a similarly named framework cell is equivalent.
- Checked numeric artifacts/configurations, hashes and no pickle loading in the
  modern inference route; local seeded RNG instead of resetting caller state.
- Independent mathematical reference tests and negative/contract cases.
- Separate generation, assessment, selection and provenance; complete occurrence
  retention, including duplicates, failures and incompatible proposals.
- MolSysMT-owned FASTA transport and isolated optional scientific engines.

[E1](hydramp_encoder_E1.md) records 95 passing artificial/installed checks.
[E2](hydramp_encoder_E2.md) records a passing real encoder comparison on 32
distinct token rows with repetition, permutation, partition and duplicate
controls. The [confidence campaign](hydramp_confidence_campaign.md) preserves
tokens and observed public returns on 256 distinct latent inputs, while keeping
failed probability and global near-tie ranking diagnostics. These are finite
results, not universal equivalence or an error-free-code proof.

### Product and code limitations

Modern delivery is still local and fragmented across retained candidates and
worktrees. Independent installation, modern CI, portable provider results and
release readiness remain incomplete. Some source docstrings still say
qualification is pending despite later scoped evidence; current help needs a
clear distinction from historical preparation.

A static robustness finding in modern `generation.py:149` creates
`torch.ones((count, 25))` without explicit dtype/device while validating CPU
float32 probabilities. It depends on caller PyTorch defaults. A focused
artificial regression and a matching-type/device reference are proposed;
failure was not reproduced in this audit. The same expression occurs in the
paused analogue draft. Reviewed generation source SHA-256:
`83d8a976cdfcdb64fed531db30a2e365954f0acb0f4072a3b0c5c1aaf266bd62`.

### Scientific usefulness and representation limits

The [retained H4 experiment](hydramp_h4_qualification.md) has 32 generated
proposals, 30 compatible assessments and zero joint Macrel AMP-positive/NonHemo
hits. This small predictive sample establishes neither a general failure rate
nor biological efficacy. It motivates utility evaluation, not a conclusion
that the port is broken. The original and modern sequence pools agree there.

Native heads score original token arrays, while string projection removes all
zeros, including internal zeros. Different token representations can map to one
visible sequence. Fidelity requires preserving this distinction; a new
sequence-facing prediction claim would need its own representation study.
Higher internal AMP/low-MIC-class scores do not establish experimental improvement.

The [original HydrAMP paper](https://www.nature.com/articles/s41467-023-36994-z)
combines generation, preselection and experimental evaluation. Modern runtime
compatibility does not transfer that biological evidence to arbitrary new routes
or selections. Independent predictive assessment, leakage controls, novelty,
diversity, chemistry and cost-aware comparison should become evaluation priorities.

### PeptideMT extensibility

[`InputRecord.issues`](../src/peptidemt/inputs.py) embeds the current Macrel
admission restrictions. [`ResultSet` reception](../src/peptidemt/results.py)
requires Macrel-specific fields, labels and categories. This is consistent with
D35, but these types are not yet a general multi-provider/multi-family layer.
Before adding another assessor, review provider-specific admission and result
semantics without changing existing contracts or serialized results silently.

PeptideMT can grow through qualified specialized resources. HydrAMP need not
provide every family. Reusing its engineering for another method is plausible;
choosing its architecture as the best multi-family basis remains unproven and
requires new endpoints, data and comparative evaluation.

## Recommended priorities and recorded follow-up

Consolidate current capabilities and product boundaries; resume analogue work
only when the pause is lifted; design a prospective utility evaluation before
expanding architecture. Preserve justified numerical improvements without
indefinitely pursuing legacy approximation identity.
