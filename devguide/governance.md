# PeptideMT development governance

Read this map and root `AGENTS.md` before starting work. The root
[MOLSYSSUITE_GUIDE.md](../MOLSYSSUITE_GUIDE.md) is the synchronized operational
summary; its linked central policies and registered inventories are authoritative.
This local map applies them to PeptideMT. It does not freeze another policy copy,
replace the full guide or make every optional capability a dependency.

## Local work and common owners

The mandatory root entry delegates the complete shared policy set to
[MOLSYSSUITE_GUIDE.md](../MOLSYSSUITE_GUIDE.md), including tools, contribution
routes, owning-issue feedback, domain ownership and release/resource rules.
Use its common policy index and the actual registered provider guides when a
boundary becomes applicable; do not keep another copied common-rule table here.

PeptideMT owns the peptide-specific design question, scientific requirements,
occurrence mappings, evaluation/selection policy, composition and interpretation
under its approved scientific work order. Review `design_methodology.md`, D35/D36
and M1–M8 before implementation. The common owner map routes molecular-system
operations to MolSysMT, visualization to MolSysViewer and topography to TopoMT;
actual missing capabilities are reported to those owners with consumer evidence.
Preserve the separate responsibilities of Praxis, Recorda, Sabueso, Nextia and
MolSys-AI. Do not create speculative runtime dependencies or new scientific scope.

The local source-only package's commands are in root `AGENTS.md`. The named
shared environment is the routine workspace; member recipes remain clean
CI/qualification fixtures. Read [the optional-engine review](optional_engine_review.md)
when the commissioned W2 boundary actually appears.

## Current evidence and limits

[W0 engineering receiving](archive/complete_w0.md) records the official starter,
genuine immutable policy/admission, baseline source/installed checks and fresh
fifteen-member shared integration. Tool/guide delivery, active instruction review,
runtime adoption, scientific tests and public artifacts are different claims.

The [W1 core](w1_core.md), tracked in uibcdf/peptidemt#4, adds engine-free
proposal ingestion, attributed saved results and two exact selectors. Input
incompatibilities and output anomalies are preserved scientific result data.
Simple public type/count/policy errors need no generic digestion dependency;
optional-provider availability/diagnostics remain the W2 boundary. See the
[W1 record](archive/implement_w1.md) for the per-boundary applicability review. No runtime dependency,
physical-quantity conversion or molecular-system implementation is introduced.

The post-delivery FASTA ownership review is tracked in uibcdf/peptidemt#5 and
provider uibcdf/molsysmt#513. General format interpretation must be delegated to
MolSysMT with a qualified source-preserving route. The current local parser is
a visible migration gap; its behavioral tests do not establish provider adoption.
See the [consumer migration record](pending_proposals/delegate_fasta_to_molsysmt.md).

The [W2 native boundary](w2_macrel.md), tracked in PeptideMT #6, advances with
in-memory inputs and MolSysMT-owned serialization. It introduces DepDigest and
SMonitor at the actual optional boundary. Engine-free controls do not qualify
Macrel or complete the live scientific work. Host bounds, installed bundle/terms
and native parity remain explicit W3 prerequisites.

The investigator's governance clarification supersedes only the historical
W0-only reporting restriction. D35/D36, M1–M8, scientific acceptance and publication
authority remain unchanged. No source-only engineering check qualifies Macrel
or another scientific model. This local map must be updated with the owning
change when an applicable boundary or accepted working instruction changes.
